### 第 8 天：文件权限深入

**第 1 步：看懂 ls -l 的输出**

```bash
ls -l /etc/passwd
ls -l /etc/shadow
ls -l /bin/bash
```

输出示例：

```text
-rw-r--r-- 1 root root  2847 /etc/passwd
-rw------- 1 root root  1234 /etc/shadow
-rwxr-xr-x 1 root root 1113504 /bin/bash
```

**第 2 步：拆解每一列的含义**

以 `-rwxr-xr-x` 为例，拆成 4 部分：

| 位置 | 字符 | 含义 |
|------|------|------|
| 第 1 位 | `-` | 文件类型（`-` 普通文件，`d` 目录，`l` 软链接） |
| 第 2-4 位 | `rwx` | 文件所有者（owner）的权限 |
| 第 5-7 位 | `r-x` | 所属组（group）的权限 |
| 第 8-10 位 | `r-x` | 其他人（other）的权限 |

权限数字对照：`r = 4`（读），`w = 2`（写），`x = 1`（执行）。所以 `rwxr-xr-x = 755`。

**第 3 步：动手练习**

```bash
# 1. 创建测试文件
cd ~
echo "hello" > test.txt
ls -l test.txt        # -rw-rw-r-- = 664

# 2. 加执行权限
chmod +x test.txt
ls -l test.txt        # -rwxrwxr-x = 775

# 3. 数字方式改权限
chmod 600 test.txt    # -rw------- 只有所有者能读写

# 4. 改所有者
sudo chown root:root test.txt
```

**第 4 步：理解目录权限的特殊性**

目录的 `x` 权限表示能不能进入目录（`cd` 进去），不是执行什么东西。

**验收标准**：

1. 能说出 rwxr-xr-x 每个部分代表什么。
   - 答：读写行、读行、读行（所有者拥有读写执行，组和其他只有读和执行）。
2. 能解释为什么 /etc/shadow 是 600 权限。
   - 答：只有所有者能读写（shadow 存密码哈希，安全敏感）。
3. 能预判 chmod 755 test.txt 之后的权限。
   - 答：-rwxr-xr-x（所有者拥有全部权限，所有组及其他只有读和执行的权限）。

### 第 9 天：SUID/SGID 权限

**第 1 步：什么是 SUID**

SUID = Set User ID。普通程序运行时用运行者的权限；但设置了 SUID 的程序，不管谁运行，都以文件所有者的权限运行。

最典型例子是 `passwd` 命令：

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x 1 root root ... /usr/bin/passwd（注意那个 s 就是 SUID）
```

为什么 passwd 需要 SUID？普通用户改密码要写 `/etc/shadow`，而它只有 root 能写。所以 passwd 设置了 SUID，谁运行都以 root 权限运行。

**第 2 步：找出系统中所有 SUID 文件**

```bash
sudo find / -perm -4000 -type f 2>/dev/null
# 常见的：/usr/bin/passwd、/usr/bin/sudo、/usr/bin/su、/usr/bin/mount
```

**第 3 步：SUID 的安全风险**

危险的 SUID = 攻击者提权的入口。如果一个 SUID 程序是 root 拥有，且能执行命令（如 find、vim、bash），普通用户运行它就能拿 root 权限。

**第 4 步：动手做一个 SUID 提权实验**

```bash
# 1. 复制 bash 到 /tmp
cp /bin/bash /tmp/mybash
# 2. 给 mybash 设置 SUID（所有者 root）
chmod u+s /tmp/mybash
ls -l /tmp/mybash      # -rwsr-xr-x 1 root root ... /tmp/mybash
# 3. 切到普通用户
su kali
# 4. 运行带 SUID 的 bash（-p 保持有效用户 ID，这是关键）
/tmp/mybash -p
# 5. 查看当前身份
whoami   # 输出：root！
```

**验收标准**：

1. 能说出 SUID 是什么意思。
   - 答：Linux 权限特殊位，属于文件特殊权限，只对可执行文件生效，以文件主人的身份来执行程序。
2. 能找到系统中的 SUID 文件。
   - 答：`sudo find / -perm -4000 -type f 2>/dev/null`。
3. 能理解为什么 SUID 是提权的重要入口。
   - 答：如果这个文件属主是 root，那么任何普通用户执行这个程序，进程都会临时拥有 root 权限。提权的根本来源：普通用户 → 临时 root 身份。

### 第 10 天：iptables 防火墙

**第 1 步：查看当前防火墙状态**

```bash
sudo iptables -L -n
```

**第 2 步：理解 iptables 的三个链**

| 链名 | 作用 |
|------|------|
| INPUT | 进入本机的流量 |
| OUTPUT | 从本机出去的流量 |
| FORWARD | 经过本机转发的流量 |

**第 3 步：动手配置规则**

```bash
# 1. 先允许 SSH（22 端口）！否则远程连不上
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
# 2. 允许本机回环（127.0.0.1）
sudo iptables -A INPUT -i lo -j ACCEPT
# 3. 允许已建立的连接
sudo iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
# 4. 拒绝其他所有入站流量
sudo iptables -A INPUT -j DROP
# 5. 查看规则
sudo iptables -L -n -v
```

**第 4 步：删除规则（恢复默认）**

```bash
sudo iptables -F
sudo iptables -L -n
```

**验收标准**：

1. 能看懂 iptables -L 的输出。
   - 答：INPUT 是目标是本机的数据包（别人访问本机）；OUTPUT 是本机向外发出的包；FORWARD 是穿过本机转发的包（本机做路由器才用到）。
2. 能配置「只允许 SSH，其他全拒绝」的规则。

```bash
# 允许访问本机 22 端口（SSH）
iptables -A INPUT -p tcp --dport 22 -j ACCEPT
# 设置 INPUT 链默认策略为 DROP
iptables -P INPUT DROP
```

3. 知道为什么要先允许 SSH 再设置默认拒绝。
   - 答：iptables 的默认策略修改立即生效，如果先设置默认 DROP，此时 SSH 放行规则还不存在，现有 SSH 连接会被直接断开，服务器远程锁死。因此必须先添加允许 SSH 的规则，再配置默认拒绝。

### 第 11 天：日志分析

**第 1 步：找到日志文件位置**

```bash
ls /var/log/
```

| 文件 | 内容 |
|------|------|
| /var/log/auth.log | 登录认证日志（SSH、su、sudo） |
| /var/log/syslog | 系统全局日志 |
| /var/log/apache2/access.log | Apache 访问日志 |
| /var/log/apache2/error.log | Apache 错误日志 |

**第 2 步：分析登录日志**

```bash
# 看所有 sshd 日志
grep -a "sshd" /var/log/auth.log
# 只看密码失败记录
grep -a 'sshd.*Failed password' /var/log/auth.log
# 统计失败 IP（按次数降序）
grep -a 'sshd.*Failed password' /var/log/auth.log | grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' | sort | uniq -c | sort -rn
# 看成功登录
sudo grep -a "Accepted" /var/log/auth.log
# 看失败登录（暴力破解痕迹）
sudo grep -a "Failed password" /var/log/auth.log
```

**第 3 步：分析 Apache 访问日志**

```bash
# 最近 20 条
sudo tail -20 /var/log/apache2/access.log
# 统计访问 IP（次数从高到低）
awk '{print $1}' /var/log/apache2/access.log | sort | uniq -c | sort -rn
# 查找 sqlmap / union select 注入特征
grep -E "sqlmap|union.*select" /var/log/apache2/access.log
# 统计 HTTP 状态码（200、404、500 等）
awk '{print $9}' /var/log/apache2/access.log | sort | uniq -c | sort -rn
# 查找 404 请求
grep " 404 " /var/log/apache2/access.log
# 看 gz 压缩旧日志
zcat /var/log/apache2/access.log.2.gz | grep -E "sqlmap|union.*select"
```

**验收标准**：

1. 能找到登录日志和 Web 日志的位置。
   - 答：系统登录认证日志（当前 `/var/log/auth.log`，轮转旧 `/var/log/auth.log.1`），记录 SSH、sudo、账号密码登录等认证事件，读取时文件会提示二进制，需要加 `-a` 参数强制按文本解析。Apache Web 访问日志（当前 `/var/log/apache2/access.log`，归档历史 `access.log.1`，压缩归档 `access.log.2.gz`）。
2. 能用 grep/awk 统计出暴力破解的 IP。
   - 答：新版 Kali 日志带 ISO 时间戳，旧教程 `awk '{print $11}'` 失效会提取端口，应使用正则提取 IP：`grep -a 'sshd.*Failed password' /var/log/auth.log | grep -oE '[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+' | sort | uniq -c | sort -rn`。本次实验结果：检索到 3 次 SSH 密码失败记录，攻击源 IP 127.0.0.1（本机回环，本地模拟爆破），目标账号 root，无外部 IP 爆破。
3. 能从 Apache 日志里找出异常请求。
   - 答：单个 IP 大量高频访问 → 目录扫描/爬虫；URL 包含 `union select`、`and 1=1` → SQL 注入探测；User-Agent 包含 sqlmap → sqlmap 扫描；大量 404 → 目录爆破。

### 第 13 天：目录扫描器

**第 1 步：原理**：拿一个字典，逐个访问 `http://目标/字典词`，返回 200 说明目录存在。

**第 2 步：准备字典文件**

```bash
nano dirs.txt
# 写入：admin、login、phpmyadmin、wp-admin、uploads、images、docs、backup、config、test
```

**第 3 步：写目录扫描脚本**

```python
import requests
target = "http://127.0.0.1/DVWA/"   # 注意末尾带 /
with open("dirs.txt", "r") as f:
    dirs = f.read().splitlines()      # 自动去掉每行末尾换行符
print(f"开始扫描 {target}，共 {len(dirs)} 个目录...\n")
for dir_name in dirs:
    url = target + dir_name
    try:
        response = requests.get(url, timeout=3)  # 3 秒超时防止卡死
        if response.status_code == 200:
            print(f"[+] 发现目录: {url}")
        elif response.status_code == 403:
            print(f"[!] 禁止访问: {url}")
    except Exception as e:
        pass   # 网络超时、连接失败直接跳过
print("\n扫描完成！")
```

**第 4 步：运行扫描**

```bash
sudo systemctl start apache2
python3 dir_scan.py
```

**验收标准**：能写出能跑的目录扫描器；能扫出 DVWA 的常见目录；理解为什么要用字典爆破——答：网站隐藏目录无法通过首页链接发现，字典内置 Web 系统常见目录名称，自动批量尝试访问，发现后台、上传目录等敏感路径，属于 Web 信息收集手段。

### 第 14 天：正则表达式提取信息

**第 1 步：基础正则语法**

| 符号 | 含义 | 例子 |
|------|------|------|

### 第 17 天：Cookie 深入

**第 1 步：查看 Cookie**：DVWA 登录页 F12 → Application → Cookies → http://127.0.0.1。

**第 2 步：理解 Cookie 的属性**

| 属性 | 安全意义 |
|------|---------|
| HttpOnly | 有了它 JS 读不到 Cookie（防 XSS 偷 Cookie） |
| Secure | 只有 HTTPS 才传（防明文被抓） |

| Domain | 哪个网站能读 |
| Path | 哪个路径下能读 |
| Expires | 过期时间（Session Cookie 关浏览器就没） |

**第 3 步：动手验证**：Console 执行 `document.cookie`，若 Cookie 设了 HttpOnly，JS 读不到。

### 第 18 天：同源策略

**第 1 步：什么是同源**：两个 URL「同源」需三个都相同：协议、域名、端口。

| URL 1 | URL 2 | 同源？ |
|-------|-------|--------|
| http://example.com | http://example.com/about | 是（路径不同没关系） |
| http://example.com | https://example.com | 不是（协议不同） |
| http://example.com | http://api.example.com | 不是（域名不同） |
| http://example.com | http://example.com:8080 | 不是（端口不同） |

**第 3 步：同源策略限制了什么**：不同源之间不能读对方 Cookie、LocalStorage、DOM，Ajax 请求默认跨域被限制。

**验收标准**：能判断两个 URL 是否同源；能说出同源策略限制了什么；知道 CORS 是什么。
